# 🚀 MOIT (모잇)

### 📢 MOIT = **Meet + It = MOIT**

같은 관심사와 목표를 가진 사람들이 모여 함께 성장하는 목적형 커뮤니티 플랫폼
**MOIT(모잇)** 는 스터디, 프로젝트, 운동, 취미 활동 등 **공통의 관심사와 목표를 가진 사람들이 모임을 만들고 참여할 수 있는 목적형 커뮤니티 플랫폼**입니다.

단순한 친목 중심의 커뮤니티가 아닌, 같은 목표를 가진 사용자들이 효율적으로 연결되고 활동할 수 있는 환경을 제공하는 것을 목표로 합니다.

---

## 🎯 기획 의도

최근 청년 세대 사이에서는 단순한 친목 모임보다 스터디, 프로젝트, 운동, 취미 활동 등 특정 목적을 중심으로 모이는 **'목적형 모임' 문화**가 확산되고 있습니다.

하지만 다양한 소모임 정보가 여러 플랫폼에 분산되어 있어 사용자가 자신의 관심사와 목적에 맞는 모임을 찾기 어렵고, 원하는 활동에 참여하기까지 많은 시간과 노력이 필요합니다.

이에 **MOIT**는 관심사와 활동 목적을 기반으로 소모임을 쉽고 빠르게 탐색하고 참여할 수 있는 플랫폼을 제공하여, 사용자들이 보다 효율적으로 새로운 사람들과 연결될 수 있도록 기획되었습니다.

> MOIT는 단순한 친목 중심 플랫폼이 아닌, 같은 목표를 가진 사람들이 효율적으로 연결될 수 있는 목적형 커뮤니티 플랫폼을 지향합니다.

## 💡 트러블슈팅

### 1. [페이징] 관리자 신고 목록 오류

**문제**

* 관리자 신고 목록에서 페이지를 이동할 때 일부 데이터가 누락되거나 예상한 조회 범위와 다르게 표시되는 문제가 발생했습니다.

**해결**

* Controller에서 전달되는 페이지 번호와 실제 데이터 조회 시 사용하는 범위 계산 로직을 수정했습니다.

**성과**

* 페이지 이동 시 신고 데이터가 일관된 기준으로 조회되도록 개선했습니다.
* 요청 파라미터부터 실제 DB 조회 조건까지 이어지는 페이징 데이터 흐름을 이해할 수 있었습니다.

---

### 2. DB 값과 JSP 화면의 수정 시간 불일치

**문제**

* DB에는 신고 수정 시간이 정상적으로 저장되어 있었지만 신고 상세 화면에서는 수정 시간이 표시되지 않는 문제가 발생했습니다.

**해결**

* 전달 경로를 추적하여 updated_at 컬럼 누락 확인 후 View까지 전달되도록 변경했습니다.

**성과**

* DB와 화면에 표시되는 데이터가 일치하도록 수정했습니다.
* 화면에서 발생한 문제를 DB부터 Mapper, DTO, View까지 단계별로 추적하며 계층 간 데이터 전달 흐름을 이해할 수 있었습니다.

## 📝 회고

JSP와 MyBatis를 활용해 사용자 신고 CRUD와 관리자 처리 기능을 구현하며, 화면 요청부터 Controller, 데이터 처리, Mapper, DB 저장 및 조회까지 이어지는 전체 데이터 흐름을 경험했습니다.

특히 화면에서 발생한 문제를 단순히 UI 문제로 판단하지 않고 DB → Mapper → DTO → View까지 데이터 전달 과정을 직접 추적하면서 문제의 원인을 찾는 경험을 할 수 있었습니다.

또한 개발 과정에서 반복되는 조회 로직과 화면·백엔드가 결합된 구조를 경험하며 역할 분리와 유지보수성의 중요성을 느꼈습니다.

이러한 경험을 바탕으로 이후 버전에서는 **Spring Boot 기반 구조로 전환하고 신고 기능을 더욱 확장하여 유지보수성과 운영 안정성을 개선하는 방향으로 발전시켰습니다.**
