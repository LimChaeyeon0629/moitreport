# 🚀 MOIT (모잇)

### 📢 MOIT = **Meet + It = MOIT**

같은 관심사와 목표를 가진 사람들이 모여 함께 성장하는 목적형 커뮤니티 플랫폼

**MOIT(모잇)** 는 스터디, 프로젝트, 운동, 취미 활동 등 **공통의 관심사와 목표를 가진 사람들이 모임을 만들고 참여할 수 있는 목적형 커뮤니티 플랫폼**입니다.

2차 프로젝트에서 Spring Boot 기반 구조와 AI·외부 연동 기능을 확장한 후, 3차 프로젝트에서는 **React/Next.js 기반 프론트엔드 전환과 함께 신고 처리 동시성 제어, 신뢰도 연계, Audit Log, AI/RAG 기반 관리자 판단 보조 기능을 추가하여 실제 운영 상황을 고려한 신고 관리 체계로 고도화했습니다.**

### 3차 고도화

#### 1. 신고 처리 동시성 제어
동일 신고에 대해 여러 관리자가 동시에 처리할 경우 발생할 수 있는 **중복 승인·반려 및 신뢰도 중복 차감 문제를 방지하기 위해 Redis Lock 적용**  
Lock 획득 후 DB에서 신고 상태가 `PENDING`인지 다시 확인하여 이미 처리된 신고가 재처리되지 않도록 구현

**성과**
* 동시 요청 상황에서도 신고 상태와 회원 신뢰도 데이터의 정합성을 유지할 수 있도록 개선

## 💡 트러블슈팅

### 1. [동시성] Redis Lock을 통한 중복 신고 처리 방지

**문제**
* 여러 관리자가 동일 신고를 동시에 승인하거나 반려할 경우 회원 신뢰도가 중복으로 변경되고 Audit Log가 중복 저장될 가능성이 있었습니다.

**해결**
* 신고 ID를 기준으로 Redis Lock을 적용했습니다.
* Lock 획득 후 DB에서 해당 신고의 상태가 `PENDING`인지 다시 확인하여 이미 처리된 신고가 재처리되지 않도록 구현했습니다.

**성과**
* 동시 요청 상황에서 중복 승인·반려 및 신뢰도 중복 반영을 방지하고 신고 상태와 관련 데이터의 정합성을 유지할 수 있도록 개선했습니다.

---

### 2. [외부 연동] 이메일 발송과 핵심 트랜잭션 분리

**문제**
* 신고 처리 과정에서 이메일 서비스의 응답이 지연되거나 발송에 실패할 경우 핵심 신고 처리 로직까지 영향을 받을 가능성이 있었습니다.

**해결**
* `@TransactionalEventListener(phase = AFTER_COMMIT)`을 적용하여 신고 처리 트랜잭션이 정상적으로 커밋된 이후 이메일 이벤트가 실행되도록 분리했습니다.
* `@Async`를 적용하여 이메일 발송을 비동기로 처리하고, 실패한 이메일은 스케줄러를 통해 다시 발송할 수 있도록 구성했습니다.

**성과**
* 신고 처리 로직과 이메일 발송 로직의 결합도를 낮췄습니다.
* 외부 이메일 서비스의 지연이나 실패가 핵심 트랜잭션에 미치는 영향을 최소화했습니다.

---

### 3. [AI / RAG] LLM 판단의 근거 부족 문제 개선

**문제**
* 신고 내용만 LLM에 직접 전달할 경우 서비스 내부 신고 정책이나 기존 처리 사례가 충분히 반영되지 않아 판단 근거의 일관성이 떨어질 수 있었습니다.

**해결**
* 운영 정책과 기존 신고 사례를 Chunk 단위로 구성했습니다.
* 신고 내용과 관련성이 높은 문서를 검색하여 OpenAI API의 Context에 함께 전달하는 RAG 구조를 적용했습니다.
* 검색된 정책 및 유사 사례와 신고 원문을 함께 전달하여 관리자가 참고할 수 있는 분석 결과를 생성하도록 구현했습니다.

**성과**
* 단순 GPT API 호출에서 벗어나 서비스 내부 정책과 기존 신고 사례를 함께 참고하는 관리자 신고 판단 보조 기능으로 확장했습니다.

## 📝 회고

3차 프로젝트에서는 기능 구현에 그치지 않고 **동시성, 데이터 정합성, 외부 서비스 장애와 같은 실제 운영 상황을 고려한 백엔드 구조를 설계하고 구현하는 경험**을 할 수 있었습니다.

특히 동일 신고를 여러 관리자가 동시에 처리할 경우 발생할 수 있는 중복 처리 문제를 Redis Lock과 DB 상태 재검증을 통해 제어하면서, 애플리케이션에서 동시 요청을 다룰 때 데이터 정합성을 함께 고려해야 한다는 점을 경험했습니다.

또한 `AFTER_COMMIT`과 `@Async`를 활용하여 이메일 발송을 핵심 트랜잭션과 분리하고, 실패한 이메일을 다시 처리할 수 있는 구조를 구성하면서 외부 서비스 장애가 핵심 비즈니스 로직에 미치는 영향을 줄이는 방법을 경험했습니다.

OpenAI API와 RAG를 활용한 신고 판단 보조 기능을 구현하면서는 단순히 AI의 응답을 사용하는 것보다 **서비스 내부 정책과 기존 사례를 함께 제공하여 판단 근거를 보완하는 과정이 중요하다는 점**을 확인했습니다.

또한 담당 신고 기능뿐 아니라 연계된 팀 기능까지 통합 테스트하여 약 11건의 오류와 사용성 개선점을 발견하면서, 개별 기능 구현뿐 아니라 **서비스 전체 흐름을 직접 검증하는 과정의 중요성**을 경험했습니다.
